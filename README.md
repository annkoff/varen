# VAREN — сайт строительной компании

Full-stack сайт строительной компании VAREN (с 2005 года, работает по всей России): каталог проектов, услуги, калькулятор стоимости, форма заявки с загрузкой файлов, Telegram-уведомления менеджеру, защищённая админ-панель с заявками, экспортом в Excel, реферальными ссылками, аналитикой и когортами, интеграция с Яндекс Метрикой.

> Тестовый проект. Проекты, отзывы, заявки и аналитика в seed — **демо-данные** (помечены `isDemo` и подписями на сайте). Фотографии — из набора референсов владельца проекта; перед коммерческим запуском замените их собственными.

## 1. Возможности

**Сайт**
- Главная: hero, позиционирование, направления, избранные проекты, преимущества, «ваш проект или наш», процесс, цены, отзывы, FAQ, CTA, контакты с картой.
- Проекты: 12 домов, фильтры по материалу и этажности, отдельная страница каждого проекта (параметры, «В этом проекте выполнено», доп. объекты, галерея по категориям с лайтбоксом, свайп/клавиатура, отзыв, «следующий проект»).
- Услуги: 5 направлений + детальные страницы.
- О компании, Стоимость (тарифы + калькулятор + формула), Отзывы, Контакты (карта Яндекса), Политика конфиденциальности, 404.
- Калькулятор с живым пересчётом и передачей параметров в заявку.
- Форма заявки: валидация, мультивыбор услуг, до 5 файлов с прогрессом загрузки, защита от двойной отправки и спама, страница успеха.
- SEO: title/description, Open Graph, favicon, sitemap.xml, robots.txt, JSON-LD, семантичная разметка, человекочитаемые URL.
- Адаптивность 320–1440+ px, мобильное меню, тёмный «архитектурный» дизайн.

**Админ-панель** (`/admin`, только после входа)
- Дашборд: новые заявки, конверсия, состояние интеграций.
- Заявки: поиск, фильтры (статус, услуга, регион, источник, даты), пагинация, карточка заявки, файлы (открыть/скачать), статусы, заметка менеджера, повторная отправка в Telegram, удаление.
- Экспорт в настоящий `.xlsx` (с учётом фильтров).
- Проекты: создание, редактирование, публикация, «на главной», порядок, загрузка фото (авто-сжатие в WebP), категории и подписи фото, обложка, удаление.
- Отзывы: добавление, редактирование, привязка к проекту, публикация.
- Реферальные ссылки: создание (код генерируется автоматически), копирование одной кнопкой, клики / уникальные / заявки / конверсия, архив.
- Аналитика: периоды (сегодня, вчера, 7 дней, 30 дней, месяц, год), визиты, уникальные посетители, заявки, конверсия, CTA, телефон, email, источники, воронка, графики, недельная сводка, когорты.
- Настройки: контакты сайта, все цены калькулятора, смена пароля, тест Telegram, удаление демо-данных.

## 2. Стек

| Слой | Технология | Почему |
|---|---|---|
| Фреймворк | **Next.js 16** (App Router, React 19, Turbopack) | SSR/SEO, API и фронтенд в одном проекте, простой деплой |
| Язык | **TypeScript** (strict) | типобезопасность от БД до UI |
| Стили | **Tailwind CSS 4** | единая дизайн-система через токены `@theme` |
| БД | **PostgreSQL 17** | надёжность, массивы, JSON, оконные функции для когорт |
| ORM | **Prisma 6** | миграции, типизированный клиент |
| Валидация | **Zod 4** | одна схема для клиента и сервера |
| Авторизация | собственные сессии: bcrypt + токен в БД (HMAC) + httpOnly cookie | никаких внешних сервисов, полный контроль |
| Файлы | локальный диск **или** любой S3-совместимый бакет (AWS SDK v3) | VPS и облако без изменений кода |
| Изображения | `next/image` (AVIF/WebP), `sharp` | быстрые страницы, сжатие загружаемых фото |
| Excel | **ExcelJS** | настоящий OOXML `.xlsx` |
| Графики | **Recharts** | лёгкие SVG-графики |
| Telegram | Bot API через `fetch` | без лишних зависимостей |
| Тесты | **Playwright** | реальный браузер, сквозной сценарий |

## 4. Требования

- **Node.js ≥ 20.9** (проверено на 24 LTS), npm ≥ 10
- **PostgreSQL ≥ 14** (проверено на 17) — локально, в Docker или облачный
- Git

## 5. Установка

```bash
git clone https://github.com/<you>/varen.git
cd varen
npm install                # postinstall сам выполнит prisma generate
cp .env.example .env       # Windows: copy .env.example .env
```

Заполните в `.env` минимум: `DATABASE_URL`, `AUTH_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`.

```bash
# сгенерировать AUTH_SECRET
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

> npm ≥ 11 по умолчанию блокирует install-скрипты пакетов. Список разрешённых (`prisma`, `@prisma/*`, `sharp`, `esbuild`) уже записан в `package.json → allowScripts`. Если npm всё же предупредит — выполните `npm approve-scripts --allow-scripts-pending` и `npm rebuild`.

## 6. Запуск локально

```bash
npm run db:migrate         # создать таблицы
npm run db:seed            # демо-каталог + админ
npm run dev                # http://localhost:3000
```

- Сайт: **http://localhost:3000**
- Админка: **http://localhost:3000/admin** (логин/пароль — `ADMIN_EMAIL` / `ADMIN_PASSWORD`)

## 9. Seed

`npm run db:seed` (идемпотентный, можно запускать повторно):
- создаёт администратора из `ADMIN_EMAIL` / `ADMIN_PASSWORD`, **если его ещё нет** (существующий пароль не трогает);
- создаёт/обновляет 12 проектов (фото, загруженные через админку, не удаляются), 6 демо-отзывов, 4 реферальные ссылки, настройки контактов и цен;
- генерирует **демо-аналитику** за 60 дней (~2 300 посетителей, ~21 000 событий, ~95 заявок) — только если её ещё нет. Все такие записи помечены `isDemo`.

Дополнительно:
```bash
npm run db:reset-demo                      # пересоздать демо-аналитику
node --env-file=.env --import tsx prisma/seed.ts --no-demo   # каталог без демо-аналитики
```
Удалить демо-заявки и демо-аналитику можно в **Админка → Настройки → Демо-данные**.

## 10. Telegram

Уведомление приходит менеджеру сразу после каждой заявки: номер, дата, имя, телефон, email, регион, услуги, площадь, описание, параметры калькулятора, предварительная стоимость, источник, реферальный код, количество файлов и кнопки **«Открыть заявку»** / **«Открыть админку»**.

### Создание бота
1. Откройте в Telegram **[@BotFather](https://t.me/BotFather)** → `/newbot`.
2. Введите имя (например, `VAREN Заявки`) и username, оканчивающийся на `bot` (например, `varen_leads_bot`).
3. BotFather пришлёт токен вида `1234567890:AA...` → это `TELEGRAM_BOT_TOKEN`.

### Получение chat id
- **Личные сообщения:** напишите боту `/start`.
- **Группа менеджеров:** создайте группу, добавьте бота, напишите в группе любое сообщение.

Затем:
```bash
npm run telegram -- chats     # выведет id чатов, которые писали боту
```
Скопируйте нужный id (у групп он отрицательный, например `-1001234567890`) в `TELEGRAM_CHAT_ID`.

### Проверка
```bash
npm run telegram -- check     # данные бота
npm run telegram -- test      # тестовое сообщение в TELEGRAM_CHAT_ID
```
Или **Админка → Настройки → Telegram → «Отправить тестовое сообщение»**.

### Важно
- Токен хранится **только** в переменных окружения, в коде и в БД его нет.
- Кнопки со ссылками Telegram принимает только для публичных `https://` адресов. Локально (`http://localhost`) бот присылает ссылку на заявку текстом — это ожидаемо.
- Статус доставки сохраняется в заявке (`отправлено / ошибка / не настроен`), из карточки заявки можно отправить повторно.
- Уведомление отправляется после ответа пользователю (`after()`), поэтому медленный Telegram не задерживает форму.

### Команды бота (опционально, webhook)
На сервере с публичным HTTPS-адресом:
```bash
# TELEGRAM_WEBHOOK_SECRET — любая случайная строка в .env
npm run telegram -- webhook https://ваш-домен.ru
```
Команды: `/id` — показать id чата, `/leads` — последние 5 заявок (только в чате менеджеров). Webhook проверяет секрет в заголовке `X-Telegram-Bot-Api-Secret-Token`.

## 11. Яндекс Метрика

1. Создайте счётчик на [metrika.yandex.ru](https://metrika.yandex.ru) → «Добавить счётчик», укажите домен сайта.
2. Скопируйте номер счётчика (только цифры) в **`NEXT_PUBLIC_YANDEX_METRIKA_ID`**.
3. Пересоберите проект (`NEXT_PUBLIC_*` подставляются на этапе сборки) и перезапустите.

Счётчик подключается только если ID задан. Включены вебвизор, карта кликов, точный показатель отказов; переходы между страницами SPA отправляются как `hit`.

**Цели** — создайте в Метрике цели типа «JavaScript-событие» с идентификаторами:

| Идентификатор | Действие |
|---|---|
| `cta_click` | клик по кнопке призыва (параметр `label` — какая кнопка) |
| `phone_click` | клик по телефону |
| `email_click` | клик по email |
| `project_view` | просмотр страницы проекта |
| `gallery_open` | открытие галереи |
| `calculator_start` | начало работы с калькулятором |
| `calculator_change` | изменение параметров калькулятора |
| `form_start` | начало заполнения формы |
| `form_submit` | успешная отправка заявки |
| `contacts_open` | блок контактов появился на экране |

**Данные Метрики в админке (опционально).** Чтобы на странице «Аналитика» показывались визиты/посетители/отказы из Метрики:
1. Создайте приложение на [oauth.yandex.ru](https://oauth.yandex.ru) с доступом **«Яндекс.Метрика: получение статистики» (`metrika:read`)**.
2. Получите OAuth-токен: `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>`.
3. Укажите его в `YANDEX_METRIKA_OAUTH_TOKEN`.

## 12. Файловое хранилище

Файлы клиентов **никогда** не лежат в `/public` и не доступны по прямой ссылке: скачать их может только авторизованный администратор через `/api/admin/files/:id`.

| `STORAGE_DRIVER` | Где хранится | Когда использовать |
|---|---|---|
| `local` (по умолчанию) | папка `STORAGE_LOCAL_DIR` (`./storage`, в git не попадает) | локально, VPS, Docker с volume |
| `s3` | приватный S3-совместимый бакет | Vercel и любые serverless/облачные платформы |

**Пример — Yandex Object Storage:**
1. Создайте **приватный** бакет (доступ на чтение — «Ограниченный»).
2. Создайте сервисный аккаунт с ролью `storage.editor`, выпустите статический ключ доступа.
3. `.env`:
   ```
   STORAGE_DRIVER="s3"
   S3_ENDPOINT="https://storage.yandexcloud.net"
   S3_REGION="ru-central1"
   S3_BUCKET="varen-files"
   S3_ACCESS_KEY_ID="..."
   S3_SECRET_ACCESS_KEY="..."
   ```
Так же работают Selectel, VK Cloud, Cloudflare R2 (`S3_REGION=auto`), AWS S3, MinIO (`S3_FORCE_PATH_STYLE=true`).

**Ограничения файлов заявки:** до 5 файлов, PDF/JPG/JPEG/PNG/WEBP, до `MAX_UPLOAD_MB` МБ каждый. Проверяются расширение, заявленный MIME-тип **и сигнатура содержимого** (переименованный `.exe` → `.pdf` будет отклонён). Файлы, загруженные без отправки заявки, удаляются через 24 часа. Фото каталога из админки сжимаются в WebP ≤ 2000 px.

## 13. Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `DATABASE_URL` | да | строка подключения PostgreSQL |
| `AUTH_SECRET` | да | секрет для сессий, ≥ 32 символов |
| `SITE_URL` | да в prod | публичный адрес сайта (`https://varen.ru`) — Telegram, sitemap, robots |
| `NEXT_PUBLIC_SITE_URL` | да в prod | то же для metadataBase / Open Graph (на этапе сборки) |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | для seed | первый администратор |
| `TELEGRAM_BOT_TOKEN` | для Telegram | токен бота |
| `TELEGRAM_CHAT_ID` | для Telegram | чат менеджеров |
| `TELEGRAM_WEBHOOK_SECRET` | нет | секрет webhook бота |
| `STORAGE_DRIVER` | нет | `local` / `s3` |
| `STORAGE_LOCAL_DIR` | нет | папка для `local` |
| `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_FORCE_PATH_STYLE` | для `s3` | параметры бакета |
| `MAX_UPLOAD_MB` | нет | лимит одного файла (по умолчанию 10; на Vercel ≤ 4) |
| `NEXT_PUBLIC_YANDEX_METRIKA_ID` | нет | номер счётчика Метрики |
| `YANDEX_METRIKA_OAUTH_TOKEN` | нет | данные Метрики в админке |
| `NEXT_OUTPUT` | нет | `standalone` — минимальная серверная сборка (Docker) |

Все переменные проверяются при старте (`src/lib/env.ts`), при ошибке выводится понятное сообщение.

## 14. Администратор

- Первый админ создаётся `npm run db:seed` из `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
- Создать ещё одного или **сбросить пароль**:
  ```bash
  npm run admin:create -- owner@example.com "НовыйНадёжныйПароль"
  ```
  (все активные сессии этого админа завершаются).
- Сменить пароль из интерфейса: **Админка → Настройки → Пароль администратора**.

## 16. Deploy

### Вариант 1 — VPS / Docker (рекомендуется для российского хостинга: Timeweb Cloud, Selectel, Yandex Cloud VM)

```bash

# заполните: AUTH_SECRET, SITE_URL, NEXT_PUBLIC_SITE_URL, ADMIN_EMAIL, ADMIN_PASSWORD,
```

Без Docker: Node 20+, PostgreSQL, `npm ci && npm run build && npm run db:deploy && npm run db:seed && npm run start` под pm2/systemd.

### Вариант 2 — Vercel + Neon + S3

1. **БД:** создайте проект на [neon.tech](https://neon.tech) (или Supabase), скопируйте connection string (`?sslmode=require`).
2. **Файлы:** создайте приватный S3-бакет (раздел 12). Локальный диск на Vercel не сохраняется — `STORAGE_DRIVER=s3` обязателен.
3. **Импорт:** Vercel → *Add New Project* → выберите репозиторий GitHub.
4. **Build Command:** `npm run db:deploy && npm run build` (миграции применяются при каждом деплое).
5. **Environment Variables:** `DATABASE_URL`, `AUTH_SECRET`, `SITE_URL`, `NEXT_PUBLIC_SITE_URL` (= домен Vercel или свой), `STORAGE_DRIVER=s3`, `S3_*`, `MAX_UPLOAD_MB=4` (лимит тела запроса Vercel — 4,5 МБ), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `NEXT_PUBLIC_YANDEX_METRIKA_ID`.
6. **Seed и админ** — один раз с локальной машины, указав production `DATABASE_URL`:
   ```bash
   DATABASE_URL="postgresql://...neon..." ADMIN_EMAIL=... ADMIN_PASSWORD=... npm run db:seed
   ```
7. Ограничение частоты запросов в памяти работает в пределах одного инстанса; основные лимиты (вход, заявки с одного телефона) дополнительно проверяются по БД.

6. Автоматически: `BASE_URL=https://домен ADMIN_EMAIL=... ADMIN_PASSWORD=... node tests/e2e.mjs` (с доступом к той же БД).

## 17. Как работает referral tracking

1. Менеджер создаёт ссылку в **Админке → Реферальные ссылки**: вводит название источника, код генерируется автоматически (`Instagram весна` → `instagram-vesna`, при совпадении добавляется суффикс) или задаётся вручную.
2. Ссылка вида **`/r/instagram-vesna`** (или эквивалентная `/?ref=instagram-vesna`). UTM-метки на ссылке сохраняются: `/r/instagram-vesna?utm_campaign=spring`.
3. `/r/<code>` проверяет, что ссылка активна, ставит cookie `varen_ref` (90 дней) и перенаправляет на `/?ref=<code>&utm_...`.
4. На первой странице клиентский трекер (`src/lib/analytics/client.ts`):
   - читает `ref` и `utm_*`, внешний referrer;
   - сохраняет **атрибуцию** в `localStorage` (+ cookie) на 90 дней: источник, ref-код, UTM, страницу входа, referrer, время. Правило — **последний непрямой переход**: прямые заходы атрибуцию не перезаписывают;
   - отправляет `page_view` с `landingRef` — сервер записывает **клик** (`ReferralClick`) с id посетителя;
   - убирает `?ref=` из адресной строки, чтобы перезагрузка или пересланная ссылка не считались повторным кликом.
5. Посетитель ходит по сайту: Главная → Проекты → Калькулятор → Заявка — атрибуция хранится в браузере.
6. При отправке формы атрибуция уходит вместе с заявкой; сервер проверяет код по БД (архивные ссылки игнорируются), при отсутствии данных в `localStorage` берёт код из cookie. В заявке сохраняются `source`, `refCode`, `referralLinkId`, `landingPage`, `referrer`, `utm*`, `attributedAt`, тип устройства.
7. Статистика ссылки: **клики** (переходы), **уникальные** (разные посетители), **заявки**, **конверсия** = заявки / уникальные.

Персональные данные для трекинга не собираются: id посетителя — случайный UUID, IP не хранится (используется только хэш для rate limit в памяти).

## 18. Как работает калькулятор

Формула (`src/lib/calculator/calculate.ts`) общая для браузера и сервера:

```
Дом     = площадь × цена комплектации за м² × коэф. материала × коэф. этажности
Допработы:
  дизайн / архитектурный проект / инженерия = площадь дома × цена за м²
  ландшафтный проект                        = фиксированная цена
  газон                                     = площадь газона × цена за м²
  деревья и озеленение                      = кол-во деревьев × цена по размеру + кустарники × цена
  освещение                                 = кол-во светильников × цена
  терраса                                   = площадь × цена за м²
  беседка                                   = базовая цена
  другие работы                             = индивидуально (0 в сумме, отмечается в заявке)
Итого   = округление (Дом + Допработы) до 10 000 ₽
```

Цены по умолчанию: тёплый контур от 65 000 ₽/м², предчистовая от 85 000 ₽/м², под ключ от 110 000 ₽/м², дизайн от 3 000 ₽/м², ландшафтный проект от 150 000 ₽, газон от 800 ₽/м². Коэффициенты материала: газобетон 1,0 · кирпич 1,12 · клееный брус 1,15 · каркас 0,9 · монолит 1,1. Этажность: 1 эт. 1,05 · 2 эт. 1,0 · 3 эт. 1,04. **Все цены и коэффициенты меняются в Админке → Настройки** без деплоя.

Передача в заявку: состояние калькулятора сохраняется в `localStorage`; кнопка «Оставить заявку с расчётом» открывает `/request?from=calculator`, форма показывает карточку с параметрами (её можно убрать). Со страницы проекта «Рассчитать похожий дом» открывает калькулятор с площадью, этажностью, материалом и комплектацией этого проекта. **Сервер не доверяет цене из браузера:** параметры валидируются схемой и стоимость пересчитывается заново по актуальным ценам из БД.

## 19. Как работает аналитика

Собственная first-party аналитика (без внешних сервисов) + Яндекс Метрика параллельно.

- **Посетитель** — случайный UUID в `localStorage`/cookie (1 год). **Сессия (визит)** — 30 минут без активности.
- События отправляются через `navigator.sendBeacon` на `/api/track`: просмотры страниц, CTA (любой элемент с `data-cta`), клики по `tel:` и `mailto:` (перехватываются глобально), просмотр проекта, галерея, калькулятор, форма, контакты. Боты и страницы админки не учитываются, есть rate limit.
- **Метрики:** визиты (уникальные сессии), уникальные посетители, заявки, конверсия = заявки / уникальные посетители, CTA, телефон, email, просмотры проектов, начало расчёта.
- **Источник** визита: ref-код → `utm_source` → домен внешнего referrer (yandex, google, vk, telegram…) → `direct`.
- **Периоды** считаются по московскому времени: сегодня и вчера — по часам, 7/30 дней и месяц — по дням, год — по месяцам.
- **Недельная сводка:** последние 8 недель — визиты, изменение к прошлой неделе, посетители, заявки, конверсия, лучший непрямой источник.
- **Когорты:** посетители группируются по неделе первого визита. Для каждой когорты: размер, сколько вернулось в последующие недели, сколько оставили заявку, конверсия и тепловая карта **накопительной конверсии к N-й неделе** после первого визита. Видно, сколько времени людям нужно на решение и какие недели привели более «тёплую» аудиторию.
- **Воронка:** посетители → смотрели проекты → начали расчёт → начали заявку → оставили заявку.

## 21. Безопасность

- Секреты только в `.env` (в git не попадает), шаблон — `.env.example`.
- Пароли — **bcrypt** (12 раундов). Сессии: случайный 256-битный токен в cookie `httpOnly`, `SameSite=Lax`, `Secure` в production; в БД хранится только HMAC токена; срок — 7 дней; выход удаляет сессию.
- Защита админки в два слоя: `proxy.ts` (нет cookie → редирект/401) и проверка сессии в БД в каждом layout, server action и API-маршруте. Все admin-страницы `noindex`, `no-store`.
- Брутфорс: не более 5 неудачных попыток на email и 20 на IP за 15 минут (по БД); одинаковое время ответа для существующих и несуществующих email.
- Все входные данные валидируются Zod на сервере; цена калькулятора пересчитывается сервером.
- Антиспам: honeypot-поле, минимальное время заполнения формы, лимит 5 заявок / 10 минут с IP, не более 3 заявок с одного телефона за 10 минут, идемпотентность по `formId` (двойной клик не создаёт дубль), лимит загрузок с IP.
- Файлы: проверка расширения, MIME и сигнатуры, лимит размера и количества, случайные имена в хранилище, защита от path traversal, скачивание только админом с `Content-Disposition: attachment` и `nosniff`.
- CSRF: `SameSite=Lax` cookie, проверка `Origin` в публичных POST, встроенная проверка Origin у server actions.
- Заголовки: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, HSTS; `poweredByHeader` отключён.
- JSON-LD экранируется, пользовательский ввод в Telegram — HTML-escape.

## 22. Тестирование

При запущенном сервере (`npm run dev` или `npm run start`):

```bash
node --env-file=.env tests/e2e.mjs          # сквозной сценарий в реальном Chromium + проверки в БД
node --env-file=.env tests/responsive.mjs   # 22 страницы × 320/390/768/1024/1440 px
```
Перед первым запуском: `npx playwright install chromium`. Тест создаёт и затем удаляет свои данные (оставить: `KEEP_E2E=1`).

`e2e.mjs` проверяет: главную, каталог, страницу проекта, галерею (лайтбокс, клавиатура), услуги; калькулятор (площадь, материал, комплектация, допработы, точная сумма); передачу параметров в заявку; валидацию; загрузку файлов с прогрессом, отклонение поддельного PDF, лимит 5 файлов; двойной клик; сохранение заявки, файлов и расчёта в БД; статус Telegram; защиту админки (редирект, 401 для API и файлов, поддельная cookie, неверный пароль); вход, поиск, карточку, скачивание файла, смену статуса; xlsx (формат, колонки, число строк); создание реферальной ссылки и сохранение источника и UTM через 4 страницы на мобильном; счётчики ссылки; аналитику за все периоды; запись всех типов событий; управление каталогом (создание, фото, публикация, скрытие, удаление); защиту Telegram webhook.

Дополнительно: `npm run typecheck`, `npm run lint`.
